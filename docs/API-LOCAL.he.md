# מפתחות API ומודלים מקומיים

[English](API-LOCAL.md)

**לפני חיבור ספק:** בדקו בעצמכם את תנאי השימוש העדכניים של הספק. האחריות לעמוד בהם היא שלכם. תנאים יכולים להשתנות, וחיבור שעובד היום עלול להפסיק לעבוד. StellarCortex אינו אומר ששימוש בחשבון או במנוי של ספק כלשהו מותר, ואינו קשור לאף ספק. פרטים ב[תנאי הספקים](../README.he.md#provider-terms).

StellarCortex תומך בכמה חיבורי API אישיים, לצד חיבורי OpenAI API, Claude API ומנוע מקומי. חיבורי ChatGPT/Codex ו־Claude Code דרך מנוי ממשיכים לפעול בנפרד. לכל בוט בוחרים את הספק והמודל שלו, ואפשר להעביר משימות גם בין ספקים שונים.

## הגדרת חיבור

פתח **הגדרות → מודלים וחיבורים → הוספת ספק API**. בחר ספק, תן לחיבור שם והדבק את המפתח שקיבלת ממנו. לספק מוכר הכתובת מתמלאת אוטומטית; לספק אחר הזן את כתובת ה־API מתוך התיעוד שלו. שמירת החיבור טוענת את רשימת המודלים, והספק מתווסף לבורר שבתחתית שיחת הבוט. בחר שם את הספק והמודל הרצוי. אין צורך להקליד שם מודל בהוספת ספק.

אפשר להוסיף כמה חיבורים, גם לאותו ספק עם חשבונות שונים. לכל חיבור שם, מפתח, רשימת מודלים ושימוש נפרדים. מזהה מודל ידני נשאר אפשרות מתקדמת למקרה שהספק אינו מפרסם רשימה. מפתח ריק בעריכת חיבור משאיר את הקיים; הסרת מפתח נעשית בכפתור נפרד. אין להדביק מפתחות בשיחות עם בוטים.

המפתח מאמת את החשבון; **כתובת השרת ופורמט הבקשות** קובעים איך מתחברים. אין פורמט אוניברסלי לכל API. בחיבור הכללי נתמכים שלושה פורמטים זורמים: Chat Completions, Responses ו־Anthropic Messages. שם הפורמט אינו מגביל את החיבור לחברה בעלת אותו שם.

| ספק | כתובת בסיס | פורמט |
| --- | --- | --- |
| NVIDIA | `https://integrate.api.nvidia.com/v1` | Chat Completions |
| OpenCode · Chat / GPT | `https://opencode.ai/inference/openai/v1` | Chat Completions או Responses, לפי התבנית שבחרת |
| OpenCode · Claude | `https://opencode.ai/inference/anthropic/v1` | Anthropic Messages |
| OpenAI | `https://api.openai.com/v1` | Responses |
| ספק אחר | כתובת הבסיס בתיעוד שלו | אחד משלושת הפורמטים הנתמכים |

ב־OpenCode, לדוגמה, מודלי GPT משתמשים ב־Responses ומודלי Claude ב־Messages. תבניות נפרדות ממלאות את הפורמט והכתובת המתאימים; אפשר להוסיף כמה חיבורים עם אותו מפתח. רשימת המודלים נטענת מ־`https://opencode.ai/inference/v1/models`. בהגדרות המתקדמות של ספק אחר אפשר לציין כתובת קטלוג שונה, באותו שרת בלבד. הרשימה שהספק מפרסם יכולה לכלול מודלים שאינם מתאימים לפורמט שנבחר; בדוק את הפורמט בתיעוד הספק. החיבור אינו מנחש אותו מתוך שם המודל. פורמטי Gemini ו־SystemOne אינם נתמכים. לפי התיעוד הנוכחי של OpenCode, מודלי צ'אט חינמיים מסוימים דורשים את לקוח OpenCode עצמו; שימוש חיצוני כפוף להרשאות ולמסלול אצל הספק.

חיבור API מחויב אצל ספק ה־API בנפרד מהמנוי. StellarCortex אינו עובר אליו אוטומטית אם מנוי מגיע למגבלה. בדיקת חיבור קוראת את רשימת המודלים, ללא בקשת יצירה. זמינות ברשימה אינה מבטיחה הרשאת שימוש, יתרה או תמיכה בכל האפשרויות בזמן משימה.

## מנועים מקומיים

בחר מנוע והזן את כתובת שירות ה־API שכבר פועל אצלך. חיבור מקומי וספק API מותאם יכולים להשתמש בכתובות loopback,‏ LAN ו־tailnet. שירותי metadata של ענן נחסמים בשני המקרים, בכל צורת כתובת וגם דרך DNS.

| מנוע | כתובת ברירת מחדל |
| --- | --- |
| Ollama | `http://127.0.0.1:11434/v1` |
| llama.cpp | `http://127.0.0.1:8080/v1` |
| LM Studio | `http://127.0.0.1:1234/v1` |
| vLLM | `http://127.0.0.1:8000/v1` |

החיבור משתמש ב־`GET /v1/models` וב־`POST /v1/chat/completions` עם פלט זורם. אפשר לשנות כתובת ופורט ולהגדיר מפתח אם השרת דורש אימות. בשרת שאינו מציג רשימת מודלים ניתן להזין מזהה ידנית; הוא מסומן כלא מאומת עד להפעלה, ובדיקת הרשימה אינה מוצגת כאילו הצליחה.

**StellarCortex אינו מתקין מנוע, מוריד מודל או מפעיל שרת מודלים.** הפעל את השירות המתאים בעצמך. אין מעבר אוטומטי למודל ענן. אם המנוע שהגדרת מנתב לענן, הניתוב והחיוב שלו נקבעים בהגדרותיו.

הכתובת נפתחת מהמחשב שמריץ את שרת StellarCortex. `127.0.0.1` בתוך Docker מתייחס לאותה מכולה, ולא למחשב שמציג את הדפדפן. אם מנוע המודל נמצא במחשב אחר, הזן כתובת נגישה מאותה סביבת שרת. ב־Docker Desktop ניתן בדרך כלל להשתמש בשם `host.docker.internal`. אין צורך לפרסם שרת מודלים פתוח לאינטרנט.

## יכולות הבוט

כלים, העברת משימות, זיכרון, שגרות ודפדפן עוברים דרך מנוע StellarCortex המשותף. כדי שהמודל יפעיל אותם עליו לתמוך ב־tool calling, ועל שרת המודל להשתמש בתבנית ובמפרש המתאימים לו. אפשר לכבות כלים לחיבור המיועד לשיחה בלבד. צפייה בתמונות ובמסך דורשת מודל חזותי; הפעל תמונות רק כאשר המודל והשרת תומכים בכך.

רמות מאמץ ומהירות מוצגות רק כאשר ידועה תמיכה מתאימה. מהירות של מודל מקומי נקבעת בעיקר על ידי המודל, הכימות, החומרה והגדרות המנוע; אין בממשק כפתור שמבטיח שירות Priority למנוע מקומי.

למודלי API יש כלי קבצים ופקודות משותפים: קריאה ורשימה מוגבלות לתיקיית העבודה; כתיבה ופקודות דורשות אישור. פקודה שאושרה רצה תחת משתמש השרת. תיקיית העבודה אינה בידוד מערכת הפעלה לפקודות; לשימוש מבודד הפעל את StellarCortex בסביבת Linux/container/VM ייעודית.

## שימוש ושמירת מפתחות

מדי המנוי נשארים נפרדים. עבור API ומודל מקומי מוצגים מוני tokens ובקשות שנצפו דרך ההתקנה הזאת, ככל שהספק דיווח עליהם. אלה אינם יתרת אשראי, מכסת מנוי או דוח של כל החשבון. אין הערכת מחיר כאשר אין נתון אמין מהספק.

מפתחות נשלחים לשרת StellarCortex רק בעת שמירה ונשמרים מוצפנים בתיקיית `private` של הנתונים, מחוץ ל־`workspace` ולקובץ מצב השיחות. המפתח לפענוח נשמר בקובץ נפרד באותה תיקייה ומוגן בהרשאות המשתמש ככל שמערכת ההפעלה מאפשרת. ההצפנה אינה מגינה מפני מי שכבר שולט במשתמש מערכת ההפעלה. יש להגן על תיקיית הנתונים ועל גישה מרחוק לממשק. גיבוי לשחזור חייב לכלול את שני קובצי החיבור הפרטיים.

מפתחות אינם מוחזרים לדפדפן, לייצוא תבניות או לחבילות ההתקנה. בכרטיסים המובנים של OpenAI ו־Anthropic הכתובת הרשמית קבועה. בחיבור API אישי המפתח והודעות הבוט נשלחים לכתובת שהגדרת. שינוי כתובת החיבור מחייב הזנה מחדש של המפתח, כדי שמפתח שמור לא יישלח אוטומטית לשרת אחר. הפניות HTTP אינן נעקבות. החלפת חיבור מחילה את ההגדרה על משימות חדשות; משימה שכבר התחילה מסיימת עם החיבור שנלכד בתחילתה.

מקורות לחיבורים כלליים: [NVIDIA LLM API](https://docs.api.nvidia.com/nim/reference/llm-apis), [OpenCode Console models and endpoints](https://opencode.ai/v2/docs/console/models/). כתובות OpenCode עודכנו לפי התיעוד החי, שהחליף את כתובות Zen הישנות.

מקורות הממשקים: [OpenAI function calling](https://developers.openai.com/api/docs/guides/function-calling), [Claude Messages](https://platform.claude.com/docs/en/claude_api_primer), [Ollama](https://docs.ollama.com/api/openai-compatibility), [llama.cpp server](https://github.com/ggml-org/llama.cpp/blob/master/tools/server/README.md), [LM Studio](https://lmstudio.ai/docs/developer/openai-compat), [vLLM](https://docs.vllm.ai/en/latest/serving/openai_compatible_server/).

## נקודות קצה להרשאות ולעדכונים

כל הנתיבים דורשים את הסשן המאומת של ההתקנה. פעולות שמשנות מצב דורשות גם את כותרת הלקוח ובדיקת אותו מקור (same-origin).

- `GET /api/claude-permissions`: ברירת המחדל של סביבת העבודה, ההגדרה הייעודית לכל בוט, ההגדרה בפועל וסיבת חסימה אם יש.
- `PATCH /api/claude-permissions`: מצב (`manual`, `automatic`, `free`, או `inherit` לבוט), `botId` אופציונלי, ו־`confirmDangerous:true` לבחירה מסוכנת. השינוי נדחה בזמן עבודה פעילה.
- `GET /api/software-update`: הגרסה המותקנת, הבדיקה האחרונה, האם ההתקנה יכולה להתעדכן, התקדמות העדכון ותוצאת המפקח האחרונה.
- `POST /api/software-update/check`: גוף JSON ריק. נבדקת רק הגרסה האחרונה של המאגר הקבוע.
- `POST /api/software-update/apply`: ה־`version` שנבדק ו־`confirm:true`. מחזיר 202 לאחר הכנה מפוקחת, או 409 כשיש עבודה פעילה, עדכון כפול או דרישת מנהל שלא מולאה. לא מתקבלים כתובת או פקודה מהקורא.
