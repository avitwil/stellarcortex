# חיבור אפליקציות ושרתי MCP

[English](CONNECTIONS.md)

**לפני חיבור ספק:** בדקו בעצמכם את תנאי השימוש העדכניים של הספק. האחריות לעמוד בהם היא שלכם. תנאים יכולים להשתנות, וחיבור שעובד היום עלול להפסיק לעבוד. StellarCortex אינו אומר ששימוש בחשבון או במנוי של ספק כלשהו מותר, ואינו קשור לאף ספק. פרטים ב[תנאי הספקים](../README.he.md#provider-terms).

חיבורי StellarCortex מנוהלים דרך **חיבור אפליקציות** בסרגל הצד. הם נשמרים בהתקנה הזאת, בנפרד מחיבורי Codex, Claude ו־ChatGPT. בוט מכל ספק יכול למצוא ולהפעיל כלים דרך `stellarcortex_connections`, אם המודל שלו תומך בהפעלת כלים. החלפת ספק המודל אינה מחליפה את החשבון המחובר לשירות.

## שרת MCP חיצוני

בחר **הוספת שרת MCP**, תן לחיבור שם והעתק את כתובת שרת ה־MCP מתוך תיעוד הספק. כתובת API רגילה או אתר השירות אינם בהכרח שרת MCP.

- **Streamable HTTP:** מתאים לשרתים מרוחקים מודרניים. הזן כתובת מלאה, כולל נתיב כגון `/mcp`.
- **SSE:** תמיכה בשרתים שמשתמשים בתעבורה הישנה.
- **stdio:** הפעלת תוכנת שרת מקומית שכבר מותקנת. הזן פקודה, מערך ארגומנטים, תיקיית עבודה ומשתני סביבה לפי הצורך. התוכנה מופעלת במחשב או בשרת שעליו רץ StellarCortex, תחת אותו משתמש מערכת הפעלה. אין התקנה אוטומטית של שרתים.

תוצאות מחיבורים הן מידע, לא הוראות. אחרי קריאה מחיבור, פקודות מעטפת ושינויי קבצים חסומים לכל השיחה, בלי אפשרות אישור. כתובת HTTP או SSE יכולה להיות ציבורית, או ב־loopback, ב־LAN או ב־tailnet. שירותי metadata של ענן נחסמים לפני כל בקשה, בכל צורת כתובת וגם דרך DNS.

בחר את צורת האימות שהשרת דורש: ללא אימות, Bearer token, מפתח בכותרת HTTP מותאמת או OAuth בדפדפן. בחיבור OAuth, היישום מגלה את שרת ההרשאות ומפעיל כניסה עם PKCE. שרת שלא תומך ברישום לקוח אוטומטי עשוי לדרוש Client ID והגדרות שהונפקו עבור StellarCortex. ההתחברות מתבצעת בחלון הספק; סיסמאות אינן נמסרות לבוט.

לחץ **חיבור**. רק משא ומתן מוצלח וטעינת רשימת הכלים ייחשבו לחיבור פעיל. אפשר לראות את הכלים שהשרת באמת מפרסם, לרענן, לנתק או להסיר חיבור. חיבור עם אותו שם בתוכנה אחרת אינו מועתק אוטומטית.

לאחר הפעלה מחדש של StellarCortex הגדרות שרתי ה־MCP נשמרות, אך צריך ללחוץ שוב **חיבור**. היישום אינו מפעיל תהליכי MCP או שולח מפתחות לשרתים אוטומטית בזמן האתחול.

שרתי MCP שונים מציעים כלים שונים. התמיכה כאן אינה מבטיחה תאימות לכל שרת, מנגנון אימות קנייני או הרחבה שאינה נתמכת. יכולות sampling/elicitation של שרת אינן מעניקות לו הרשאה להריץ מודל או לבקש סודות מאחורי הקלעים.

## Google

כדי להשתמש ב־Gmail,‏ Drive,‏ Calendar ובשירותי Google אחרים, חברו את Google דרך שירות MCP כמו Composio, עם **הוספת שרת MCP** שלמעלה. כתובת שרת יכולה לכלול מחרוזת שאילתה, כמו `user_id` של Composio. היא נשמרת מוצפנת כמו מפתח, והיישום מציג את הכתובת בלעדיה.

בגרסאות קודמות היה מחבר Google מובנה. בשדרוג, היישום מנסה לבטל את הגישה שלו ב־Google, ושוב בכל הפעלה עד ש־Google מאשרת, ומוחק את הלקוח וה־tokens של Google שנשמרו, גם מגיבויי העדכונים. בדקו ב־[myaccount.google.com/permissions](https://myaccount.google.com/permissions) שאין עוד ל־StellarCortex גישה, ומחקו את לקוח ה־OAuth שיצרתם ב־Google Cloud Console.

## שימוש בכלים ומפתחות

בקשה לבוט כגון “חפש ב־Drive את המסמך...” מפנה אותו לרשימת החיבורים והכלים הזמינים. תוצאות מכלים חיצוניים הן מידע, ואינן הוראות שמרחיבות את הרשאות הבוט. קריאות לשרתי MCP חיצוניים ממתינות לאישור שמציג את השרת, הכלי והארגומנטים. ניתוק חיבור או שינוי הגדרותיו מבטלים אישור ישן שטרם בוצע.

מפתחות, סודות OAuth ו־tokens נשמרים מוצפנים בתיקיית הנתונים הפרטית של היישום, ולא בתיקיית העבודה של הבוטים. הם אינם מוחזרים לרשימות החיבורים, לייצוא נתוני השיחות או לחבילת ההתקנה. גיבוי לשחזור חייב לשמור גם את קובץ ההצפנה; ההצפנה אינה מגינה מפני שליטה במשתמש מערכת ההפעלה שמריץ את השרת.

מקורות: [MCP client SDK](https://github.com/modelcontextprotocol/typescript-sdk), [MCP authorization](https://modelcontextprotocol.io/specification/latest/basic/authorization).
